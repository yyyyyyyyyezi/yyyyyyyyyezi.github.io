从零搭建这个博客：一次和 AI 结对的建站记录

从选方案、部署踩坑，到私密收藏、鼠标动效和更新日历，记录这个博客是怎么一步步搭起来的。

#建站#Astro#记录

写在最前(此段手打哈)：我确实想有写博客的地方，也觉得是个学习的好机会，怎么搭博客，怎么发布，怎么买域名，怎么守护自己的域名，怎么防止黑客攻击，怎么展示自己的思想和智慧。但是我只是随手在claude ops5-5的对话框里，敲下，给我搭个博客，我想要这个这个，那个那个，然后按照cmd里的要求，一步一步，这件事就做成了。接着是突发奇想的，不想自己写博客可不可以呢？“记录一下我搭博客的过程”也是这简单的一句，仅仅一句，就完成了，甚至是我的口吻，虽然读的出来，字里行间还是有很AI的地方，但是莫名有点难过啊喂！！！！ 完全没有兴奋，完全是怅然若失啊，就，年少不可得之物，这么好得吗？那我的年少算什么呢

我一直想要一个属于自己的地方：既能写点东西给别人看，求职时也能拿出来；又能把网上看到的好文章收进来，只留给自己。这篇文章记录了这个博客从无到有的过程，包括中间踩过的坑。

选方案：为什么是静态博客

一开始摆在面前的有三条路：

  • 直接用平台（公众号、知乎专栏、语雀）：最省事，但内容在别人那里，样式也改不了。
  • 自建动态博客（WordPress 之类）：功能全，但要自己维护服务器。
  • 静态博客：用 Markdown 写文章，由生成器转成网页，托管在免费平台上。

我选了第三种，框架用的是 Astro。理由很简单：免费、稳定，文章都是 Markdown 文件，以后想搬家也容易。

我还提了两个要求：

  1. 要有跟着鼠标动的效果，不想要一个死板的页面；
  2. 自己写的文章公开，网上收藏的内容私密，避免版权问题。

鼠标动效

最后做了四种效果，都用 Canvas 自己写，没有引入额外的库：

  • 粒子连线背景：背景里飘着一些点，离得近的会连成线；鼠标靠近时，附近的点被吸过来，和鼠标组成淡淡的三角形。
  • 点击烟花和涟漪：点一下，会炸开一圈彩色粒子。
  • 鼠标拖尾：光标后面拖着一条渐隐的彩带。
  • 自定义光标：一个小圆点加一个缓慢跟随的圆环，移到链接上圆环会放大。

几个细节：系统开了“减少动态效果”时，动效会全部关掉；手机上没有拖尾和自定义光标；页面切到后台时动画会暂停，省电。

私密收藏：怎么保证不泄露

这是整个项目里我最在意的部分。思路是按目录隔离：

  • src/content/posts/ 放自己写的文章，公开；
  • src/content/clips/ 放收藏，私密，只在本地预览时能看到。

用目录区分，而不是在文章里写一个“是否私密”的开关，是因为开关很容易漏写，一漏写就公开了。

另外还加了一道构建后的泄漏检查：每次构建完，脚本会扫描所有公开页面，只要发现收藏的标题、私密链接，或者和私密图片内容一样的文件，就直接让构建失败，网站也就发布不出去。后面会讲到，这道检查真的拦下过一次问题。

部署：一路踩坑

坑一：锁文件版本对不上

第一次部署到 Cloudflare 就失败了，报错说 package.json 和 package-lock.json 不一致。原因是我本地用的是 npm 11，Cloudflare 用的是 npm 10，两个版本对可选依赖的处理不一样。解决办法是用 npm 10 重新生成一次锁文件。

坑二：国内打不开

部署成功后拿到一个 workers.dev 的地址，结果发现这个域名在国内基本打不开。我的博客主要是给自己用、给面试官看，对方打不开就没意义了。

于是换成了 GitHub Pages，地址是 用户名.github.io，国内一般能访问，也不用买域名。

坑三：私有仓库不能直接发布

源码仓库是私有的（因为收藏的原文在里面），但免费账号不能从私有仓库发布 GitHub Pages。最后的做法是：

  • 源码继续放在私有仓库；
  • 另建一个公开仓库，只放构建好的网页；
  • 写了一条 npm run deploy 命令：构建 → 泄漏检查 → 推送到公开仓库。

这样公开仓库里只有网页文件，连 Markdown 源文件都没有。

坑四：git 连不上 GitHub

浏览器能上 GitHub，git 推送却一直超时。原因是浏览器走了代理，git 默认不走。给 git 单独配置一下代理就好了。

“捡文章”：一个带门槛的收藏流程

我经常在知乎上看到好文章想收藏，于是想做一个“给链接就能收进博客”的工具。为了防止自己无脑囤积，加了一条规则：每收藏一篇，必须先写至少 50 字的心得，字数不够就保存不了。

做的过程中发现：

  • 知乎不能直接抓取，脚本请求会返回 403，要求登录。我们没有去绕过它，而是改成从浏览器里导出。
  • 浏览器扩展 MarkDownload 能把网页存成 Markdown，但在知乎的问题页上经常抓错回答，因为一个页面里有好多篇回答。
  • 最后加了一种更可靠的方式：选中想要的那篇，按 Ctrl+C，脚本从剪贴板读取。选了哪篇就是哪篇。
  • 带图片的文章一开始会让页面报错，因为图片放在导出文件旁边，脚本没有一起复制过来。修好之后，导入时会自动把图片复制到收藏目录。

现在的流程是：

npm run clip -- 知乎链接          # 从剪贴板读取
npm run clip -- 导出的文件.md     # 导入 Markdown 文件

改版：从单调到“星空玻璃”

第一版能用，但太素了。改版时选了“星空玻璃”风格：

  • 半透明的毛玻璃卡片，背景里有几团缓慢流动的彩色光晕；
  • 鼠标移到卡片上，卡片会浮起、轻微倾斜，还有一块高光跟着鼠标走；
  • 首页加了个人介绍、标签云和按月归档；
  • 文章页加了阅读进度条、预计阅读时间、跟随滚动高亮的目录，以及上一篇、下一篇；
  • 右上角可以切换深色和浅色，会记住你的选择。

还加了一个我很喜欢的东西：像 GitHub 那样的更新日历。最近一年每天一个格子，哪天更新了文章，那天就亮起来：一篇是天蓝色，篇数越多颜色越深。

几个有意思的 bug

圆环乱跳

鼠标移到按钮上时，跟随的圆环会突然跳到别的位置。原因是圆环的位置写在 transform 里，悬停时又用 scale 把它放大了 1.65 倍，结果浏览器把位移也一起放大了，离屏幕左上角越远，跳得越远。把位置改成单独的 translate 属性，问题就解决了。

私密图片差点混进公开网站

改版后的第一次构建，泄漏检查报错了：一张私密收藏里的图片，被打包进了公开网站的目录。

原来，虽然私密页面没有生成，但 Astro 构建时会把所有收藏文章里引用的图片都处理一遍。修复办法是：正式构建时，干脆不加载私密收藏，只有本地预览时才加载。

这次构建失败了，所以图片没有被发布出去。这道检查当初是“以防万一”加的，没想到真的派上了用场。

卡片倾斜太猛

卡片的倾斜效果一开始太夸张，看起来像在往下陷。把倾斜角度从 6° 降到 2°，浮起高度从 6px 降到 3px，现在舒服多了。

写在最后

回头看，这个博客的技术本身并不复杂，花时间最多的反而是那些“想当然”的地方：版本不一致、国内网络、代理、浏览器扩展抓错内容、图片被意外打包……每个坑都不大，但都得真的踩一遍才知道。

现在，它终于是一个属于我自己的地方了。
